# Grey's Internato

Analysis of the Portuguese medical specialty matching process ("Internato
Médico" / "colocação de médicos"): how many seats each specialty/region/
hospital offered per year, who got placed where and with what ordering
number, and (eventually) a tool for a student to enter their own ordering
number and see which specialties/hospitals they could realistically get
into.

## Layout

- `data/raw/vagas/` — yearly seat-offer PDFs (`vagas-YYYY.pdf`).
- `data/raw/colocacoes/` — yearly placement-result PDFs (`YYYY-colocados.pdf`).
- `data/processed/` — generated by the pipeline, not committed:
  `vagas.csv`, `colocados.csv`, `REPORT.md` (extraction quality report),
  `extracted_text/` (raw text dump per source PDF), `ocr_cache/` (OCR
  markdown for scanned PDFs).
- `docling/` — git submodule, used only for the OCR fallback path (scanned
  PDFs). Native-text PDFs are parsed directly without it.
- `backend/` — extraction pipeline + an optional local FastAPI backend.
- `frontend/` — React + Vite app. Reads static JSON exported from the
  processed data (`frontend/public/data/*.json`), no backend required at
  runtime — deployable as-is to GitHub Pages.
- `tests/` — pytest unit tests (`test_mappings.py`, `test_processed_data.py`)
  and `check_names.py`, a non-failing script that flags suspicious
  specialty/institution names for human review.
- `notebooks/` — QA notebooks over `data/processed/*.csv` (run `make process`
  first). `01_qa_seats_by_year_location.ipynb` checks total seats by year,
  the unmapped-region rate, and specialty drift across years.
  `02_specialty_year_location_pivot.ipynb` pivots seats by specialty x year
  x location and cross-checks that `colocados` placements never exceed
  `vagas` seats. Regenerate both with
  `python notebooks/build_notebooks.py && jupyter nbconvert --to notebook --execute --inplace notebooks/*.ipynb`.

See `CLAUDE.md` for coding conventions and PDF-handling notes.

## Setup

```bash
python -m venv .venv
.venv\Scripts\activate        # or: source .venv/bin/activate
pip install -r requirements.txt

cd frontend && npm install
```

## Running the pipeline

```bash
make process   # PDFs -> data/processed/*.csv -> frontend/public/data/*.json
make report    # data/processed/REPORT.md + per-file extracted text dumps
python -m pytest tests/ -v            # structural checks on the processed CSVs
python tests/check_names.py           # data/processed/QA_FLAGS.md, names worth a glance
```

For a scanned PDF (native text extraction returns nothing), run OCR first
so `build_dataset.py` picks up the cached markdown automatically:

```bash
.venv\Scripts\python backend\ocr_convert.py data\raw\colocacoes\2024-colocados.pdf data\processed\ocr_cache\2024-colocados.md
```

This is slow (tens of minutes for a 100+ page scanned PDF — no GPU, CPU
OCR). The OCR'd `colocacoes/` files only recover specialty + ordering
number this way (`backend/extract_colocados_ocr.py`), not institution —
see Known limitations.

## Running the app

```bash
make frontend-dev     # http://localhost:5173, reads frontend/public/data/*.json
```

Optional local API (not needed for the static frontend, but useful for
querying the data directly):

```bash
make api               # http://localhost:8000
```

## Deploying to GitHub Pages

```bash
cd frontend
GITHUB_PAGES=1 npm run build
```

Publish `frontend/dist/` via a `gh-pages` branch or GitHub Actions. The
`base` path in `vite.config.js` is set for `https://<user>.github.io/EspecialidadesPT/`
— update it if the repo is renamed.

## Known limitations

**Parsing accuracy**

- **Per-year PDF layout drift.** Each year's `vagas-YYYY.pdf` can use a
  different structure. `vagas-2023.pdf` parses via position-based row
  matching (`backend/extract_vagas.py`); 2021, 2022, 2024, and (partially)
  2025 parse via `backend/extract_vagas_labeled.py` instead, which anchors
  on explicit "Subtotal"/"Total da Especialidade" labels and known
  specialty/region name patterns rather than position — full
  institution/region detail, not just totals. Accuracy varies by year
  (self-consistency checked: institution seats should sum to each
  specialty's declared total); run
  `python backend/extract_vagas_labeled.py data/raw/vagas/vagas-YYYY.pdf`
  directly to see the current mismatch count for a given year.
- **Total seats reconcile against each PDF's own printed grand total**
  ("Total Geral" 2023-2025 / "Total Nacional" 2021-2022) exactly for 2021,
  2022, and 2024, and within ~1% for 2023 and 2025 — see
  `notebooks/01_qa_seats_by_year_location.ipynb` and
  `tests/test_processed_data.py::test_vagas_total_seats_matches_official_grand_total_per_year`
  (regression guard, tolerance 200 seats/year). `build_dataset.py`'s
  `_leaf_rows_only()` keeps only the most granular level per specialty,
  falling back to the printed total when the breakdown doesn't reconcile
  with it (a mismatch means parser misattribution, not a real
  discrepancy). The residual few-percent gap for 2023 and 2025 isn't
  root-caused further than what's in the notebook — worth another pass
  against those two raw PDFs if exact-to-the-seat accuracy is needed.
- **"Medicina Geral e Familiar" nests one level deeper** than every other
  specialty (hundreds of individual clinics/USFs under each ULS), in every
  year's PDF. `build_dataset.py`'s `_leaf_rows_only` drops each ULS's own
  subtotal row (its name is always a prefix of its child USFs') so
  institution-level rows for this specialty reconcile with the printed
  total and don't double-count.

**Placement (`colocados`) data**

- **2021 and 2022's `colocados` PDFs list records as plain sequential text**
  (Nome / Especialidade / Instituição / Cédula / Nº de Ordem, five lines per
  candidate, alphabetical by name) with no ruled table grid, so
  `extract_colocados.py`'s table-based parser (built for 2023+) finds
  nothing there. `backend/extract_colocados_native_full.py` recovers full
  rows for both years instead, anchoring on known specialty names the same
  way `extract_colocados_ocr_full.py` does for OCR'd years. 2022's PDF text
  itself has some embedded-font noise (a handful of institution names come
  out with stray characters, e.g. "Fernando Fnnseca" for "Fernando
  Fonseca") — cosmetic, doesn't affect specialty or ordering number.
- **2024 and 2025 `colocacoes/` are scanned PDFs**, OCR'd and parsed
  differently depending on whether that year's OCR text preserves row
  order: 2025's does, so `backend/extract_colocados_ocr_full.py` recovers
  specialty + institution + ordering number; 2024's doesn't (institution
  names wrap across two lines in the source table and OCR scrambles the
  continuation into the next record), so `backend/extract_colocados_ocr.py`
  only recovers specialty + ordering number for it — `institution` is
  blank for that year.
- **2025's extraction truncates 2 institution names** (OCR artifact —
  "Hospital Central do Funchal" → "do Funchal", a "Centro Hospitalar..."
  → "Centro"; see `data/processed/QA_FLAGS.md`). Specialty and ordering
  number for those 2 rows (of 1,818) are still correct, only
  `institution` is truncated.
- **The prediction tool averages whatever years are loaded**, not a real
  forecast — it gets more accurate as more years' `colocados` data get
  parsed and added.

**Name normalization**

- **Institution and specialty name normalization is best-effort**, not
  exhaustive — see `backend/institution_mapping.py` (2024/2025 SNS "ULS"
  reorganization) and `backend/specialty_mapping.py` (wording variants
